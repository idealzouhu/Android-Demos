## 一、音频

### 1.1 什么是音频？

音频（Audio） 是指携**带有声信息的机械波（声波）经换能器转换为电信号后的表示形式**，在信号处理与计算机领域，通常指代经采样与量化后的数字音频信号，或其对应的原始模拟信号。



### 1.2 数字信号生成流程

#### 1.2.1 物理层面：声波的产生与传播

- **声源振动**引起周围介质（通常是空气）分子周期性疏密变化，形成**纵波形式的机械波**，即声波。

- 声波在空气中传播表现为**瞬时压强相对于大气压的偏移**，即声压。

- 人耳听觉系统的可感知频率范围约为 **20 Hz ～ 20 kHz**（随年龄与个体差异有所衰减）。



#### 1.2.2 模拟域：声电转换与模拟信号

- **传声器（麦克风）** 作为换能器，将声波引起的空气压强变化转换为**连续时间、连续幅度**的电压信号。

- 该电压信号 x(t)为**一维连续模拟信号**，其瞬时幅度正比于瞬时声压。

- 此时信号尚未数字化，可直接通过模拟电路传输或存储（如磁带、黑胶唱片）。

  

#### 1.2.3 数字域：模数转换与数字音频

- 模拟信号理论上保留了完整原始波形，但直接存储和传输会引入不可消除的噪声与衰减，且难以复制和处理；数字音频通过足够高的采样率和量化精度，可在感知上逼近甚至满足专业需求，同时具备无损复制、抗干扰、易压缩和可编程处理的巨大优势，因此现代系统普遍采用数字音频。

- 模拟信号进入 **ADC（模数转换器，Analog-to-Digital Converter）**，经历三个核心环节：

 | 阶段                     | 英文         | 说明                                                         |
  | ------------------------ | ------------ | ------------------------------------------------------------ |
  | **采样（Sampling）**     | Sampling     | 以固定时间间隔 Ts=1/fs提取信号瞬时值，fs为采样率（如 44.1 kHz） |
  | **量化（Quantization）** | Quantization | 将连续幅度映射为有限个离散电平，位深（如 16 bit）决定量化级数与动态范围 |
  | **编码（Encoding）**     | Encoding     | 将量化后的样本按特定格式组织为二进制数据流，封装为 PCM / WAV / MP3 / AAC 等容器或编码格式 |

  最终产物即为**数字音频信号**，可由处理器直接读写、存储、传输与播放。

- 奈奎斯特–香农采样定理指出：要把一个连续模拟信号无失真地数字化，采样频率必须至少是信号中最高频率成分的 2 倍；否则会发生混叠（Aliasing），无法还原原信号。
- 人耳的最高频率为 20kHz，为了满足人耳的听觉要求，采样率至少为 40kHz，通常为 44.1 kHz。



### 1.3 核心概念

| **参数**              | **定义**               | **典型值**                                                |
| :-------------------- | :--------------------- | :-------------------------------------------------------- |
| **采样率 fs**         | 每秒采集样本点数       | 8 kHz（电话）、44.1 kHz（CD）、48 kHz（影视）             |
| **位深（Bit Depth）** | 每个样本的量化精度     | 16 bit（CD 品质）、24 bit（录音室）、32 bit float（后期） |
| **声道数**            | 独立音频通道数量       | 1（Mono）、2（Stereo）、5.1 / 7.1（环绕声）               |
| **码率（Bitrate）**   | 压缩音频每秒平均比特数 | 128 kbps（MP3）、256 kbps（AAC）、1411 kbps（CD PCM）     |



### 1.4 音频编码格式

#### 1.4.1 为什么要编码

音频编码的核心目的是解决 PCM 裸数据的存储与传输痛点：

- **减小数据量**：PCM 的数据量极大，以 CD 品质为例（44.1 kHz × 16 bit × 2 ch），码率约为 1.41 MB/s（≈1411 kbps）。经编码压缩后可降至 128～320 kbps（MP3 / AAC），节省 70%～90% 的存储空间与传输带宽。
- **便于存储与传输**：裸 PCM 流缺乏必要的元信息（采样率、位深、声道数），无法被播放器直接识别。编码后将 PCM 封装为标准格式（如 WAV / MP4 / OGG），携带完整的描述信息，适用于网络流媒体、本地文件存储、蓝牙音频传输等场景。



#### 1.4.2 常见音频编码格式

**（1）无压缩格式（PCM / WAV）**

| 格式           | 说明                                         |
| -------------- | -------------------------------------------- |
| **PCM**        | 原始量化样本流，非文件格式，需搭配容器使用   |
| **WAV / AIFF** | PCM + 文件头封装，无压缩，音质最佳，体积最大 |

------

**（2）无损压缩格式（可 100% 还原 PCM）**

| 格式     | 特点                                              |
| -------- | ------------------------------------------------- |
| **FLAC** | 开源免费，压缩率约 50%～60%，广泛用于 Hi‑Res 音频 |
| **ALAC** | Apple 无损格式，特性与 FLAC 类似                  |
| **APE**  | Monkey's Audio，压缩率较高，但生态支持相对有限    |

------

**（3）有损压缩格式（去除人耳不敏感信息）**

| 格式              | 特点                                     | 常见码率              |
| ----------------- | ---------------------------------------- | --------------------- |
| **MP3**           | 普及最早，兼容性最强                     | 128 / 192 / 320 kbps  |
| **AAC**           | 编码效率优于 MP3，移动端与流媒体主流格式 | 96～256 kbps          |
| **Opus**          | 超低延迟 + 高音质，适用于 VoIP / WebRTC  | 6～510 kbps（自适应） |
| **Vorbis（OGG）** | 开源免专利费，曾广泛用于游戏与网页       | —                     |



## 二、视频

### 2.1 什么是视频？

**视频（Video）** 是由一系列按时间顺序排列的**静态图像（视频帧）**与同步的**音频流**共同组成的时序媒体。

每一帧本质是一张位图图像（通常用 YUV / RGB 色彩空间表示），以足够高的速率（如 24～60 fps）连续播放时，利用人眼视觉暂留效应形成连续运动的视觉感受。



### 2.2 核心概念

| **参数**                     | **定义**                                        | **典型值**                                                   |
| :--------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| **分辨率（Resolution）**     | 单帧图像的像素尺寸（宽 × 高）                   | 720×480（SD）、1280×720（HD）、1920×1080（Full HD）、3840×2160（4K） |
| **帧率（Frame Rate / FPS）** | 每秒显示的帧数，决定画面流畅度                  | 24/25 fps（影视）、30/60 fps（直播/游戏）                    |
| **码率（Bitrate）**          | 单位时间压缩后数据量（bps），决定画质与体积平衡 | 1080p H.264 ≈ 4～6 Mbps、720p ≈ 2～3 Mbps                    |
| **原始像素格式**             | 帧数据存储格式，常用 YUV420（比 RGB 节省带宽）  | YUV420P、RGB888                                              |





### 2.2 视频编码格式

#### 2.3.1 为什么需要编码？

- **原始视频数据量极大**：1080p（1920×1080）× 24fps × 3 字节（RGB）≈ **≈ 150 MB/s**，不经编码无法实用存储与传输。**视频编码（Codec）**通过去除**空间冗余**（帧内相似块）与**时间冗余**（帧间运动相似），将码率压缩至原始的数百分之一。
- 编码后通常再**封装（Mux）**进容器文件（如 MP4），与音频流、字幕、元数据一起存储。



#### 2.3.2 常见视频编码格式(codec)

| **格式**                   | **说明**                 | **特点**                                                     |
| :------------------------- | :----------------------- | :----------------------------------------------------------- |
| **H.264 / AVC**            | 最广泛使用的视频编码标准 | 软硬件支持极好，兼顾压缩率与兼容性（Baseline/Main/High Profile） |
| **H.265 / HEVC**           | H.264 后继者             | 同等画质下码率约降低 50%，适合 4K/8K，专利授权复杂           |
| **VP9**                    | Google 开源，无专利费    | YouTube 主力，压缩率接近 H.265，编码较慢                     |
| **AV1**                    | AOMedia 开源新一代编码   | 压缩率优于 H.265/VP9，编码极慢（逐步获硬件支持）             |
| **MPEG-2 / MPEG-4 Part 2** | 早期标准                 | 广电/DVD 遗留，已基本被 H.264 替代                           |





#### 2.3.2 视频帧类型与 GOP

视频编码通过**帧间预测**大幅压缩数据，帧分为三种基本类型：

| 类型                             | 全称                | 说明                                                         |
| -------------------------------- | ------------------- | ------------------------------------------------------------ |
| **I 帧（Intra Frame）**          | 帧内编码帧 / 关键帧 | 存完整图像，可独立解码，不需参考其他帧；是随机定位（Seek）的锚点 |
| **P 帧（Predicted Frame）**      | 前向预测帧          | 仅记录与前一 I/P 帧的差异（运动矢量 + 残差），压缩率高，需参考前帧解码 |
| **B 帧（Bi-directional Frame）** | 双向预测帧          | 记录与前一 I/P 帧及后一 I/P 帧的差异，压缩率最高，但增加解码延迟 |

**GOP（Group of Pictures）**：两个 I 帧之间的所有帧组成一组，以 I 帧开始。GOP 长度影响压缩率与随机定位速度（常见 2～4 秒一个 GOP）。





## 三、音视频容器

### 3.1 什么是音视频容器

**音视频容器（Container）** 是一种**封装格式**，负责将编码后的视频流、音频流、字幕、章节信息及元数据（如时长、码率、分辨率）打包成一个文件

| **容器**                   | **扩展名** | **特点**                                            |
| :------------------------- | :--------- | :-------------------------------------------------- |
| **MP4（MPEG-4 Part 14）**  | `.mp4`     | 最通用，跨平台，支持 H.264/H.265 + AAC，流媒体友好  |
| **MKV（Matroska）**        | `.mkv`     | 开源万能容器，支持多音轨/字幕，适合归档与媒体服务器 |
| **MOV**                    | `.mov`     | Apple QuickTime 容器，专业剪辑常用                  |
| **TS（Transport Stream）** | `.ts`      | 抗丢包，常用于直播/HLS、DVB 广播                    |
| **WebM**                   | `.webm`    | 基于 MKV，通常封装 VP9/AV1 + Opus/Vorbis，Web 原生  |



### 3.2 硬解码和软解码

- 硬解码是利用设备专用硬件解码音视频压缩数据，省 CPU、低功耗但依赖硬件支持
- 软解码是用 CPU 运行软件算法解码，兼容性最好但耗资源。

实际播放通常优先尝试硬解码，失败再降级软解码。
